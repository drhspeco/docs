Data in Getpeeko flows through a structured pipeline. You connect data sources to a project, trigger an analysis run, and the AI engine processes your data to produce insights. Those insights can then be collected into reports and shared with stakeholders. Understanding the shape of each entity helps you work with the platform more effectively and interpret results with confidence.

## Projects

A project is the container for a specific analysis scope. It holds everything needed to run and review an analysis: connected data sources, a history of runs, generated insights, and configuration settings.

Each project contains:

- **Name and description** — a human-readable label and optional context for what the project analyzes
- **Data sources** — one or more connected integrations that supply the raw data for analysis
- **Run history** — a chronological log of every analysis run executed against the project
- **Insights** — the cumulative set of AI-generated findings across all completed runs
- **Settings** — project-level configuration such as analysis frequency, notification preferences, and report defaults

Projects are scoped to a workspace. Members with the Admin or Owner role can create and delete projects; Members can view and run them.

## Analysis runs

An analysis run is a single execution of Getpeeko's AI engine. When you trigger a run, Getpeeko pulls the latest data from the project's connected sources and processes it to surface new insights.

Each run moves through the following lifecycle:

| Status | Meaning |
|--------|---------|
| `pending` | The run has been queued and is waiting for the engine to pick it up. |
| `running` | The engine is actively processing the project's data. |
| `complete` | The run finished successfully and insights are available. |
| `failed` | The run encountered an error. Check the run log for details. |

Every run record includes:

- **Timestamp** — when the run was triggered
- **Duration** — how long the engine took to complete processing
- **Status** — the current state (`pending`, `running`, `complete`, or `failed`)
- **Insight count** — the number of insights generated during that run

You can re-trigger a failed run from the project's **Runs** tab after resolving the underlying issue (such as a disconnected data source or insufficient data).

## Insights

An insight is an individual AI-generated finding produced by an analysis run. Each insight describes a specific, evidence-backed pattern or relationship in your audience data.

<AccordionGroup>
  <Accordion title="title">
    A concise label for the finding, written in plain language. For example: "Onboarding completion predicts 30-day conversion." The title is indexed for search and appears in report summaries.
  </Accordion>
  <Accordion title="finding">
    A full description of the insight, including the observed pattern and its direction. For example: "Users who complete all five onboarding steps are 3× more likely to convert within 30 days compared to users who skip at least one step." Findings are written in plain language and do not require statistical background to interpret.
  </Accordion>
  <Accordion title="confidence score">
    A numeric value between 0 and 1 indicating how strongly the underlying data supports the finding. A score above 0.8 indicates a well-supported finding; scores below 0.5 should be treated as preliminary signals that warrant further investigation.
  </Accordion>
  <Accordion title="supporting data">
    The evidence the AI engine used to generate the finding. Supporting data may include aggregated metrics, cohort comparisons, trend charts, and data point counts. Raw user-level data is never included in insights.
  </Accordion>
  <Accordion title="tags">
    Labels assigned automatically by the engine (and editable by you) that categorize the insight by theme, data source, or audience segment. Use tags to filter and organize large sets of insights within a project.
  </Accordion>
  <Accordion title="created_at">
    The timestamp of the analysis run that produced the insight. Use this field to understand which version of your data the insight reflects, especially when comparing findings across runs taken at different times.
  </Accordion>
</AccordionGroup>

## Data sources

A data source is an integration that connects an external system to Getpeeko. You attach data sources to projects to supply the raw data the AI engine analyzes.

Data sources are configured at the workspace level and can be shared across multiple projects. Supported source types include:

- **Analytics platforms** — connect tools like Mixpanel, Amplitude, or Google Analytics to bring in event and behavioral data
- **CRM systems** — connect Salesforce, HubSpot, or similar platforms to include customer lifecycle and contact data
- **Databases** — connect a cloud database or data warehouse directly using read-only credentials
- **File uploads** — upload CSV or JSON files for one-off or supplemental datasets that do not have a live integration

When you attach a data source to a project, Getpeeko syncs data from that source before each analysis run. If a sync fails, the run enters the `failed` state and the run log identifies which source caused the issue.

<Note>
  Getpeeko only requests read access to your data sources. No data is written back to connected systems. Review the permissions requested during integration setup to confirm the minimum access required.
</Note>

## Reports

A report is a curated, shareable collection of insights exported from a project. Reports are designed for stakeholders who need findings without direct access to the Getpeeko workspace.

Reports are snapshots — they capture the selected insights as they existed at the moment of export. If you run a new analysis after generating a report, the report does not update automatically. Generate a new report to reflect updated findings.

Each report contains:

- **Title and description** — set by the report creator
- **Selected insights** — a subset of the project's insights, chosen manually or filtered by tag
- **Snapshot timestamp** — when the report was generated
- **Export format** — reports can be shared via a shareable link, downloaded as a PDF, or exported as a CSV for further analysis

Reports are accessible to anyone with the share link, regardless of whether they have a Getpeeko account. If you need to revoke access, delete the report from the project's **Reports** tab.
